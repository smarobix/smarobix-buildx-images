# Maintaining smarobix-buildx-images

These pages are for people who change this repository: adding a board or an OS release, bumping a base image, changing what a `.deb` declares, cutting a release, or rebuilding the Yocto images. If you want to put ROS 2 on a board or cross-build your own workspace, start at the [home page](../index.md) instead.

## Pages

| Page | Read it when |
|---|---|
| [Add a board](add-a-board.md) | You want images, and possibly a `.deb`, for a board or OS that isn't covered yet. |
| [Add a downstream version](add-a-downstream-version.md) | A vendor image such as PYNQ, or Debian itself, ships a new release. |
| [Base images and source fixes](base-images.md) | You choose or bump a Docker base image, or a ROS source build breaks on a newer toolchain. |

| [Rebuild the Yocto images](yocto.md) | You rebuild the K26 or Raspberry Pi 5 board images, SDKs or dev containers. |

## Where things live

| Path | What it is |
|---|---|
| [`targets.yml`](https://github.com/smarobix/smarobix-buildx-images/blob/main/targets.yml) | One entry per published image tag. The single source of truth for targets. |
| [`tools/targets.py`](https://github.com/smarobix/smarobix-buildx-images/blob/main/tools/targets.py) | Turns `targets.yml` into the CI matrices, the targets reference page and the site's picker data, and checks the docs against it. |
| [`dockerfiles/`](https://github.com/smarobix/smarobix-buildx-images/tree/main/dockerfiles) | One directory per Dockerfile family: `k26`, `pynq-z1`, `rpi`, `oesdk`. |
| [`.github/workflows/build-images.yml`](https://github.com/smarobix/smarobix-buildx-images/blob/main/.github/workflows/build-images.yml) | Builds and pushes the images, packages the `.deb` files, creates releases. |
| [`.github/scripts/compute-depends.sh`](https://github.com/smarobix/smarobix-buildx-images/blob/main/.github/scripts/compute-depends.sh) | Derives a `.deb`'s `Depends` field from the built tree. |
| [`yocto/`](https://github.com/smarobix/smarobix-buildx-images/tree/main/yocto) | kas files and the `meta-smrbx` layer for the Yocto boards. |
| `docs/` | This site. |

## One fact, one owner

Board names, image tags, `.deb` names, the RMW recommendation and the tested-hardware status all come from `targets.yml`. Nothing else types them out:

- [`docs/reference/targets.md`](../reference/targets.md) is generated by `python3 tools/targets.py docs`. Never edit it by hand; change `targets.yml` and regenerate it.
- The picker on the home page reads `targets.json`, which the site build writes with `python3 tools/targets.py json`.
- `python3 tools/targets.py check-docs` fails if a Markdown page names an image tag of `ghcr.io/smarobix/smarobix-buildx-images` or a `smarobix-ros-*` package that isn't in `targets.yml`. Run it over every page before you open a pull request:

  ```bash
  python3 tools/targets.py check-docs $(git ls-files '*.md')
  ```

A page that needs a list of targets links to the [targets reference](../reference/targets.md) instead of copying it. The image-label contract belongs to colcon-buildx, which reads the labels; it is documented in [Image labels](https://smarobix.github.io/smarobix-buildx-images/tool/reference/labels/).
